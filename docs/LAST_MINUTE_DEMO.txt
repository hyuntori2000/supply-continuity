시연 원칙
지도 → 문제 → AI 제안 → 적용 → 새로운 재난 상황. 한 치킨 사건에서 끝까지 진행한다.
시연에서 제외: Traffic & timing 별도 화면, 재고 편집, 다른 상품 순회,
전체 버전 목록, 모든 배송 경로 표, 상세 JSON. 기능을 삭제한 것은 아니다.
AI가 대안을 제안하고 조건을 해석한다. 수량은 제약을 검증하는 배분 엔진이 계산한다.
복구 수량 → 우선 매장 충족 → 마지막 배송/평균 배송 시간 → 비용 순으로 제안을 평가한다.
공급 수량이 늘면 마지막 배송은 늦어질 수 있다. 모든 시간이 개선됐다고 말하지 않는다.

녹화 전
1. 로그인은 녹화 전에 완료. 접속 코드는 영상에 넣지 않는다.
2. 새로고침. 브라우저 확대는 100% 정도, 한 탭만 보여준다.
3. 아래 보고서·증빙·프롬프트 A/B를 각각 복사할 수 있게 준비한다.
4. 이전에 승인된 사건을 재활용하지 말고 New incident로 시작한다.
5. 처리 대기는 실제로 완료될 때까지 기다린다. 편집에서 대기만 줄이면
   화면에 “Processing time shortened”를 표시한다. 5분은 완성 영상 기준이다.
6. 저장된 재고가 바뀌거나 AI가 다른 유효 조건을 내면 수치가 달라질 수 있다.
   아래 값은 10/24 실제 AWS 테스트 값이며 화면에 나온 결과를 그대로 읽는다.

00:42–01:25 | 예시 1 — 새 보고서에서 시작
클릭 순서:
1. New incident
2. Example product → DEMO Raw Chicken 1 kg
3. Fill example report
4. Report store → Target · Colma 확인
5. Customer report에 아래 REPORT 입력
6. Submit & analyze new incident → 처리 완료 대기
7. Trace & evidence review가 접혀 있으면 열기
8. Evidence type → Precautionary hold — cause unconfirmed
9. Evidence reference에 아래 EVIDENCE 입력
10. Record reviewed evidence & demo hold

REPORT
Customer reported feeling unwell after eating DEMO Raw Chicken 1 kg, lot DEMO-P2-BLEND-A, purchased at Target Colma. This is a fictional demo report. Cause is unconfirmed.

EVIDENCE
Synthetic demo: batch records and lot ancestry reviewed. Record a precautionary hold pending investigation; cause remains unconfirmed.

영어: “A new report enters the system. Bedrock extracts the product and lot,
and the system traces the affected stores. A complaint does not prove
contamination, so the operator records a precautionary demo hold.”

01:25–01:55 | 기본 공급과 중단 지점
클릭: 지도 1. Original supply → 2. Interrupted.
공급처 알파벳, 매장 번호, 제한 로트와 연결된 공급망을 잠깐 보여준다.
Operational instruction에 PROMPT A → Run recovery agent.
Plan saved / AI exploration까지 완료될 때까지 기다린다.
이 버튼은 계획 저장 후 AI 대안 탐색도 자동 실행한다. Explore 버튼을 중복 클릭하지 않는다.

PROMPT A
Suppliers A, B and D can each supply at most 200 packs. Disable store transfers for this baseline. Clear operational supplier exclusions and regional traffic adjustments. Use traffic multiplier 1. Preserve all lot safety restrictions. Minimize delivery time.

영어: “The map separates the original network from restricted lots. For this
scenario, available supplier capacity is limited. The supplier-only plan covers
about 59 percent of replacement demand.”

01:55–02:50 | 핵심 장면 — AI가 먼저 제안
스크롤: AI SPECIAL SUGGESTION으로 이동.
확인: same-chain transfers를 켜는 제안, Before/After 수치.
테스트 결과: 600 → 988 packs, 58.7% → 96.7%, 부족 422 → 34 packs.
시간: 마지막 배송 547 → 569분, 평균 배송 258 → 177.7분.
클릭: Accept changes & create new version.
스크롤: 지도 3. Recovery → 공급처 문자 또는 매장 번호 하나 클릭.
대시보드도 988 packs/96.7%로 바뀌는 것을 보여준다.

영어: “The agent proposes using safe surplus from stores in the same retail
chain. The engine verifies the proposal: recovery increases from 59 to 97
percent. More stores are served, although the final delivery is later. This
tradeoff stays visible. I accept the change, and the map and dashboard update
from the same saved plan.”

탐색 실패 시: 계획은 유지된다. Explore with AI 또는 Explore alternatives again을
한 번 눌러 재시도한다. 유효 제안이 없으면 제안이 있는 것처럼 설명하지 않는다.

02:50–04:10 | 예시 2 — 산불로 추가 공급 중단
같은 사건에서 Operational instruction에 PROMPT B 입력.
클릭: Run recovery agent → 완료 후 지도 3. Recovery.
지도 문구: Current plan · dispatch excluded: A · Santa Rosa.
보여줄 내용: A는 0, 나머지 공급처와 안전한 매장 재고가 공급을 이어간다.
테스트 결과: 788 packs/77.1%, 234 packs unfilled, 마지막 배송 565분.
이 경우 96.7%에서 77.1%로 떨어지는 것은 새 재난으로 공급원이 사라졌기 때문이다.
장애 이전보다 좋아졌다고 설명하지 말고, 추가 장애에서도 유지한 공급량을 설명한다.
두 번째 AI Special Suggestion이 개선안을 찾지 못하면 그 패널은 건너뛴다.

PROMPT B
A simulated wildfire has stopped dispatch from supplier A. Keep suppliers A, B and D limited to 200 packs each. Keep same-chain store transfers enabled with a 90-minute driving limit. Set North Bay driving time to 2x. Preserve all lot safety restrictions and minimize delivery time.

영어: “Now a simulated wildfire stops supplier A, and North Bay travel takes
twice as long. Bedrock converts that report into operational constraints. The
plan excludes A and reallocates supply through the remaining sources and safe
store surplus. We retain about 77 percent coverage and explicitly show what
is still missing. This is a disaster scenario, not a live wildfire feed.”

숫자와 주장 주의
- coverage는 계획된 배분 비율이며 실제 배송 완료율이 아니다.
- 지도 연결선은 공급 관계를 보여준다. 산불 프롬프트는 공급처 제외와 지역 시간
  배수를 적용한다. 실제 도로 폐쇄 우회 경로를 계산했다고 설명하지 않는다.
- 저장된 도로 거리/기본 이동시간을 배분 계산에 사용한다. 이 시연의 2x 교통은
  사용자 입력 가정이다. 별도 Google 교통 분석은 이번 시연에서 생략한다.
- 데이터는 실제 위치를 활용한 합성 공급망/재고다. 실시간 매장 재고라고 말하지 않는다.
- 계획은 사건별로 저장되지만 공유 재고를 실제 예약하지 않는다.
- AI가 자유롭게 새로운 물류 기능을 발명하는 것은 아니다. 지원된 대안과 제약 안에서
  해석·탐색하고, 검증된 계산 결과를 비교한다.

이번 수정 검증
- 백엔드 74개 테스트 통과. 프론트엔드 30개 테스트 통과.
- 3개 상품의 재고·교통·공급 중단 조합 36개 시나리오 검증 포함.
- 더 싸지만 더 늦고 복구량이 동일한 안을 개선으로 추천하던 문제 수정.
- AI 설명의 수치/방향 오류 방지를 위해 화면 비교값은 계산 결과에서 생성.
- AI가 제목만 “enable transfers”라고 하고 실제 조건은 false로 내던 경우에
  검증된 기회를 이용한 1회 재검토 추가. 실패하면 성공을 꾸미지 않고 오류 표시.
- 이전 정책으로 저장된 추천은 재탐색 필요. 기존 계산 결과/버전은 보존.
- 중복 치킨 테스트 기록 10건을 목록에서 보관 처리. 직접 접근과 버전 기록 보존.
